Two problems, one page. .admin-tabs is complete but named for one section, and .subtab — the second-level form — has no base at all, only a __count colour fix in the dark theme. Tier 2 on ROADMAP.md.

A record page in EHSQ Enterprise routinely has two levels of tab: the record's own views (Details, Actions, Attachments, History) and a second level inside one of them. Praxis has a complete implementation of the first wearing the wrong name, and a name for the second with nothing behind it.

Per ROADMAP.md decision 2 this is an alias, not a rename — .admin-tabs keeps working forever.

Anatomy

  1. Tablist — .tabs / .admin-tabs, a flex row closed by a hairline.
  2. Tab — .tab / .admin-tab, with a 2px bottom border that carries the active state and a -1px margin so it sits on the tablist's rule rather than under it.
  3. Count — .subtab__count, a badge. Defined only as a dark-mode ink correction today.
  4. Panel — no class. The application's.

Variants

Underline (primary)Complete as .admin-tabs — teal-70 ink, teal-60 border
Second level (.subtab)Name only. Should be quieter than the primary: smaller, no rule, a pill or a text-weight change rather than a second underline. Two stacked underlines read as one broken one

ScrollableMissing. .admin-tabs uses flex-wrap, which is fine for five tabs and wrong for twelve

States

  • Active — --active. Exists.
  • Hover — ink to primary. Exists.
  • Focus-visible — missing. .admin-tab has no focus rule, so keyboard users get the UA default outline over a 2px border, which is where it is least visible.
  • Disabled — missing.
  • Contains an error — missing, and needed for the same reason as accordion: a tab hiding an invalid field must say so.

Code

Markup contract

ItemRequirement
role="tablist" / "tab" / "tabpanel"Required for the real tab pattern. If the tabs are links to separate pages they are not tabs and must not claim the roles — this distinction is the one most often got wrong
aria-selectedOn every tab, true on one
aria-controls / aria-labelledbyTab to panel and back
tabindexRoving: 0 on the active tab, -1 on the rest. Arrow keys move between tabs, Tab leaves the set
JSNeeded for roving focus and arrow keys. Praxis has none

Usage guidelines

Do

  • Use tabs for views of one thing, not for steps in a process — that is a stepper.
  • Keep the set short enough to see at once.
  • Put counts on tabs where the count is the reason to switch.

Don't

  • Give .subtab a second underline.
  • Claim role="tab" for links that navigate.
  • Hide a required field behind an unmarked tab.

Accessibility

  • Roving tabindex and arrow-key movement, or it is a row of buttons with tab paint.
  • aria-selected is the state; the border is decoration.
  • The missing focus ring is a live defect, not a planned nicety — .admin-tab ships today with no :focus-visible rule.
  • A panel with no interactive content should be focusable so a keyboard user can read it.
