.capa-prio has no base rule. The only reference to it in src/ is a WCAG contrast fix for its active step in the dark theme — a correction applied to a component that was never defined. Tier 2 on ROADMAP.md.

Every regulated record in EHSQ Enterprise moves through named stages, and the stage is usually the first thing a user needs to know: a CAPA is at containment, a permit is issued but not activated, an MOC is awaiting technical review. Praxis has one class for this — .capa-prio__step--active — and it exists only as a colour fix in the dark theme, applied over nothing.

This is the component that makes a record page legible before you read any of it.

Anatomy

  1. Track — the line connecting the steps.
  2. Step — a marker and a label. The label is not optional; a numbered circle with no name tells a user nothing about a permit.
  3. Marker — complete, current or pending.
  4. Meta — optional per step: who, when. This is what turns a stepper into a record of what happened rather than a picture of a process.

Variants

VariantUse
--horizontalUnder the page header, 3–5 stages. The default
--verticalIn a side rail, or where steps carry meta lines. Scales past five
--compactMarker only, in a table cell or a card header

Open decision: whether a step can be navigated to. A wizard's steps are links; a workflow's history is not. Making it configurable risks a stage badge that looks clickable and is not, so the safer answer is two components — and the safer default is not a link.

States

  • Complete — filled marker, success ink.
  • Current — the one place .capa-prio__step--active already has a treatment: dark ink on the bright cyan fill via --px-primary-fg, added because white on that fill measured 1.86:1.
  • Pending — outline marker, secondary ink.
  • Blocked — the state general steppers omit and this domain needs. A CAPA can be stalled waiting on evidence, and that is not "pending".
  • Skipped — permitted by some workflows. Must be visually distinct from complete or the record lies.

Markup contract

ItemRequirement
Element<ol>. The steps are ordered and that order is meaningful; a <div> stack throws it away
aria-current="step"On the current step. This is what conveys position; the class is paint
aria-labelOn the list, naming what is progressing
TrackDrawn with ::before/::after, not extra elements — a screen reader should hear four steps, not four steps and three connectors
StateClass per step. No state may be conveyed by colour alone; complete and skipped need different markers, not just different fills
JSNone

Usage guidelines

Do

  • Name every stage. "Step 3" is not a stage.
  • Show who and when on completed steps — that is the part an auditor reads.
  • Give blocked its own treatment.

Don't

  • Use it as navigation unless the steps really are navigable.
  • Show more than about five stages horizontally — go vertical.
  • Use it for a percentage. That is a progress bar, and a different thing.

Accessibility

  • aria-current="step" carries position; the fill does not.
  • Complete, skipped and blocked must differ in shape or glyph as well as colour — WCAG 1.4.1.
  • Connector lines are decorative and must not reach the accessibility tree.
  • Forced colors: every state here is a fill difference, so all five collapse to one. Needs glyphs or borders in that mode.
