Nothing exists for this. Not a timeline, not an activity feed, not an event row. Tier 2 on ROADMAP.md, and a first-class Praxis component by decision 3 there.

In nuclear, pharma and aviation the history of a record is frequently more scrutinised than its current state. Who changed the severity, when, from what, to what, and why — that is the artefact an inspector asks for. It is not an activity feed in the social sense; it is evidence.

That distinction drives every decision on this page. A social feed can be lossy, paginated by recency and summarised. An audit trail cannot: it must be complete, ordered, attributable, and printable. Praxis has no print stylesheet either (ROADMAP.md F1), so those two items are coupled.

Anatomy

  1. Rail — the vertical line carrying the sequence.
  2. Marker — one per event, typed by what happened.
  3. Actor — an avatar and a name. Never a name alone and never an avatar alone.
  4. Action — the verb phrase. "Changed severity from Medium to High".
  5. Timestamp — absolute, with timezone. See Markup contract.
  6. Detail — optional expandable diff, comment or attachment reference.

Variants

VariantUse
Full trailThe History tab of a record. Every event, oldest or newest first — see Usage
--compactThe last three events in a side rail, with a link to the full trail
--groupedEvents collapsed by actor and time window: "Marcus Silva made 4 changes". Convenient, and it must remain expandable to the individual events or it is no longer a trail
--diffField-level before and after. The variant that makes it evidence rather than a log

Open decision: whether grouping is allowed at all. It improves readability and it introduces a summarised view of a legal record. The safe position is that grouping is presentation only, always expandable, and never the printed form.

States

  • Event types — created, edited, status change, assignment, comment, attachment, approval, signature, system action. Each needs a distinct marker; nine fills alone will not carry it.
  • System versus person — must be unmistakable. An escalation fired by a scheduled job is not a decision someone made.
  • Superseded — a correction that replaces an earlier entry. The earlier entry stays visible and marked, because deleting it is the one thing an audit trail may not do.
  • Loading more — a long trail pages. Depends on loading states.

Markup contract

Usage guidelines

Do

  • Use absolute timestamps with a timezone.
  • Name the actor in text, every time.
  • Show what changed from and to, not just that something changed.
  • Keep superseded entries visible and marked.
  • Default to newest first for reading, and offer oldest first — reconstructing a sequence is easier forwards.

Don't

  • Use relative times.
  • Summarise without an expandable path to the individual events.
  • Let a system action look like a human decision.
  • Omit an event because it seems uninteresting. Completeness is the property that makes this worth having.

Accessibility

  • An ordered list, so a screen-reader user hears the sequence and its length.
  • Event type in text, not only in a marker glyph — WCAG 1.4.1.
  • <del>/<ins> rather than colour for diffs, for the same reason.
  • Expandable details follow the disclosure contract.
  • Long trails need a heading structure or landmark, or the History tab becomes one unnavigable list of four hundred items.
