The container, the header row and the panel are all undefined. praxis-rfield.css styles the tick, the child order and the collapse rotation — everything except the box. Tier 2 on ROADMAP.md.

praxis-rfield.css styles a great deal about .section — the teal tick before the header, the flex order that puts the chevron first and the title second, the -90deg rotation when .is-collapsed is set — and never defines the container, the header row or the panel. So the collapse animation works on a box that has no box.

Fields documents the current state. What is missing is the base, and a general form of it: an audit checklist is thirty collapsible groups, and it should not have to be a record form to get them.

Anatomy

  1. Container — .section. Undefined.
  2. Header — .section__header. Partly defined: the tick and the child ordering exist, the row does not.
  3. Trigger — .chevron-btn. Positioned by the header rules, otherwise undefined.
  4. Title — .section__title. Ordering only.
  5. Panel — the collapsible region. No class at all today.

Variants

VariantUse
Single disclosureOne header, one panel, independent of its neighbours. What a record form needs
AccordionA set where opening one closes the others. Rarely right for this domain — an auditor comparing two sections should not have to choose
--subsecNested. .subsec exists in praxis-rfield.css and is described there as deliberately lighter than .section__title so nesting reads without a second border

Open decision: whether to build on <details>. It gives the toggle, the keyboard behaviour and — importantly — content that is findable by in-page search even when closed, which matters for a long checklist. The cost is that its animation story is still poor and Praxis already animates this one.

States

  • Expanded — default.
  • Collapsed — .is-collapsed on the container. Already the convention, and already what rotates the chevron.
  • Contains an error — the state no general accordion has and every form needs. A collapsed section hiding an invalid field must say so on its header, or the error summary is the only route to it.

Responsive behavior

None of its own. One note that is not cosmetic: at phone width more sections should start collapsed, because a form that opens at 4,000px of scroll is unusable — but "collapsed by default" is a page decision, not a component one.

Interactive demo

The frame shows the current state — a real .section with its header parts, so the missing box is visible rather than described.

Code

praxis-rfield.css, where the partial rules already live. A general disclosure that is not a record section is an argument for praxis-core.css instead — worth settling before the base is written, because moving it later means touching both sheets.

Markup contract

ItemRequirement
aria-expandedOn the trigger, not the container. The single most common error in this pattern
aria-controlsOn the trigger, pointing at the panel id
TriggerA real <button>. Whether the whole header row is the target is an open question — a bigger target is better, but the row often carries a pill or a count that should not be part of the button
TitleA real heading at the right level. .section__title is a <p> in the current examples, which loses the document outline
Collapsed panelhidden, not height:0. A zero-height panel keeps its contents focusable, so tabbing walks into a section that is not on screen
JSNeeded for the toggle. Praxis has none for this today

Usage guidelines

Do

  • Let sections open independently.
  • Put a count or a status on the header so a collapsed section still says something.
  • Mark a section that contains an error.

Don't

  • Collapse a section that contains a required empty field on first load.
  • Use height:0 to hide the panel.
  • Nest more than two levels. .subsec is the second and there should not be a third.

Accessibility

  • aria-expanded on the trigger and aria-controls to the panel.
  • Collapsed content is hidden, so it leaves the tab order.
  • The title is a heading, so a screen-reader user can navigate the form by section.
  • The chevron is decorative; the button needs a real accessible name, which is what the .visually-hidden span in the proposed markup is for.
  • Respect prefers-reduced-motion for the rotation and any height transition.
