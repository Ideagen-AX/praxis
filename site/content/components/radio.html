praxis-core.css restyles input[type="checkbox"] on the bare element — 16px, 4px radius, 1.5px border, filled with --praxis-color-text-primary rather than the brand teal, with hover, checked, indeterminate and focus states. There is no equivalent for radio.

.pillset/.pill in Fields covers picklists-as-radios and is good. This is about the plain case: two options in a settings row.

Variants

Bare element, and a group. .pillset stays the answer for a picklist.

States

Match the checkbox exactly: rest, hover, checked, focus-visible, disabled. There is no indeterminate for radio. A radio group can be entirely unselected, which a checkbox cannot, and that state needs to be valid-looking rather than error-looking.

Accessibility

Arrow keys move within a group and only the selected radio is in the tab order — that is native behaviour and is lost the moment the element is replaced with divs. The focus ring must not be removed: as Form controls already says about checkboxes, the fill alone does not indicate focus.
