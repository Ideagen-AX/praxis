.admin-table is a good table and praxis-toolbar-compact.css already ships .colmenu (column visibility) and .sortmenu. Everything past that is missing, and the missing part is what separates a table from a grid.

An auditor working a 1,284-row register needs to pin the reference column, widen the finding text, drop six columns they do not care about, and have that arrangement still be there tomorrow.

States

  • Row hover, selected, and selected while filtered — "12 selected, 4 not visible" is a real and dangerous state for a bulk action.
  • Column being resized or dragged.
  • Pinned-column seam.

Responsive behavior

A grid does not become a phone layout by shrinking. The two workable answers are a card-per-row transformation or horizontal scroll with a pinned identity column; picking one is the main open decision.

Markup contract

Stays a real <table> wherever possible. Pinning is CSS position:sticky; reorder and resize need script and both need keyboard equivalents. Bulk selection needs a live region reporting the count, and it must state how many selected rows are outside the current filter.

Token reference

--px-hover for rows (the faint wash, correct for a large target), --px-hover-btn for header controls, --admin-row-selected already exists for selection. Missing: a density scale and a pinned-column seam shadow.

Accessibility

Sort state via aria-sort. Resize and reorder must be keyboard-operable or they are decoration. Virtualised rows break screen-reader row counts unless aria-rowcount is set — the trap that makes virtualisation an accessibility decision rather than a performance one.
