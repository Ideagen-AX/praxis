There is a date control, and you cannot use it. .filter-date, .filter-date-range and .cf-date-range are all scoped to praxis-filters.css. A .rfield date field is a bare text input. Tier 2 on ROADMAP.md.

Dates carry unusual weight in this domain. An incident has a date occurred and a date reported and the gap between them is a compliance metric. A permit has a validity window. A CAPA has a due date that drives escalation. Getting a date wrong is not a typo, it is a finding.

So the important part of this component is not the calendar — it is the text input beside it. A user who knows the date types it; the calendar is for the user who is counting back from today.

Anatomy

  1. Text input — the primary entry path. Must accept a typed date.
  2. Trigger — opens the calendar. An .iconbtn-sized button.
  3. Calendar panel — a .px-pop surface.
  4. Grid — weeks as rows.
  5. Footer — Today, Clear.

Variants

VariantUse
SingleDate occurred, due date
RangePermit validity, report period. Two inputs, one panel, with the second bounded by the first
With timeIncidents need it — "14:20 on 3 March" is materially different from "3 March". Undecided whether time is part of this component or a sibling
Relative presetsLast 7 days, this quarter. Belongs to the filter form, not the record form. .filter-date-range is where this already lives

States

  • Empty / filled / invalid — the invalid case needs aria-invalid and an inline message, wired to the error summary.
  • Out of range — a future date on "date occurred" is not a format error, it is a logic error, and the message should say which.
  • Disabled dates — before a record was opened, after today.
  • Today — marked in the grid, distinctly from selected.

Code

New sheet, or praxis-controls.css. It needs a script — a calendar grid with keyboard navigation is not CSS — which argues for its own file so a page that only needs the text input does not pay for the panel.

Markup contract

ItemRequirement
InputText, not type="date", if a custom panel is used — the two together give a browser picker and a Praxis picker on one field
Format hintA visible example, wired with aria-describedby. GOV.UK's research is unambiguous that this reduces errors more than any placeholder
Gridrole="grid" with arrow-key navigation, per APG
Panelrole="dialog", Escape closes, focus returns to the trigger

Usage guidelines

Do

  • Let the user type. The calendar is the fallback, not the path.
  • Show a format example beside the label.
  • Say why a date is rejected — "cannot be in the future", not "invalid".

Don't

  • Use a calendar for a date of birth or any date far from today.
  • Combine type="date" with a custom panel.
  • Put relative presets on a record field. They belong in filters.

Accessibility

  • Typing must always work. A calendar-only date field is a keyboard trap for anyone who knows the date.
  • Grid follows APG: arrows move by day, PageUp/Down by month, Home/End to week bounds.
  • Escape closes and restores focus.
  • The format hint is associated with aria-describedby, not left as placeholder text — placeholders vanish on focus, which is when they are needed.
  • Announce the selection in words, not digits.
