Zero rules. No upload control, no attachment list, no drop zone, no progress. Tier 2 on ROADMAP.md.

An incident without a photo is a weaker record. An audit finding without evidence is contested. A CAPA without the closing document is not closed. Attachments are not a peripheral feature in this domain — they are frequently the substance of the record — and Praxis has no way to draw one.

Anatomy

  1. Drop zone — with a visible button, because drag-and-drop alone is not keyboard reachable.
  2. Constraints line — accepted types and max size, before the picker opens.
  3. Attachment row — name, size, type glyph, remove.
  4. Progress — per file.
  5. Thumbnail — for images. .thumb exists in praxis-admin.css and may be reusable.

Variants

VariantUse
SingleA signature image, one certificate
MultipleThe common case. Incident photos

Camera capturePhone only. capture="environment" on the input, which is one attribute and materially changes field use

States

  • Idle / dragging-over / uploading / complete / failed.
  • Rejected — wrong type or too large. Must name which, and must not silently drop the file.
  • Scanning — the state this domain adds. Regulated deployments virus-scan before an attachment is available, so "uploaded" and "usable" are different moments and the UI has to say so.

Responsive behavior

Desktop: drop zone plus button. Phone: no drop zone — there is nothing to drag from — so it becomes a pair of buttons, "Take photo" and "Choose file". Dropping the drop zone at phone width is the correct behaviour, not a degradation.

Usage guidelines

Do

  • State types and size limits before the picker opens.
  • Keep a visible button. Drag-and-drop is an enhancement.
  • Distinguish uploaded from scanned from available.

Don't

  • Rely on accept for validation.
  • Remove a file without confirmation once it is part of a submitted record — that is an alert dialog.
  • Show a drop zone on a phone.

Accessibility

  • The file input is the control; the drop zone is decoration over it.
  • Progress and completion announced, not only drawn.
  • Remove buttons name their file.
  • Drag-and-drop has no keyboard equivalent, which is precisely why the button is required rather than optional.
