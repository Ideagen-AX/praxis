.appbar__avatar is the only avatar in Praxis and its name binds it to the app bar. Tier 2 on ROADMAP.md.

A small component with a lot of callers once the domain patterns land: an assignee on a CAPA row, the author of a comment, the signatory on an attestation, every actor in an audit trail. Three of those four are also on this roadmap, so this is the shared dependency.

Anatomy

  1. Frame — circle, fixed size, never distorted.
  2. Content — photo, initials, or a fallback glyph.
  3. Ring — a border separating it from whatever it sits on. .appbar__avatar already does this and changes the ring per theme.
  4. Group — an overlapping stack with an overflow count.

Variants

VariantNote
Photobackground: center/cover, as .appbar__avatar does
InitialsThe common case. One or two letters, teal fill
SystemAn action taken by an integration or a scheduled job. An audit trail needs this and it must not look like a person
GroupOverlapping, with +3
SizesThree: 20px inline, 28px in a row, 34px in chrome (the existing size)

Open decision: whether initials get a colour derived from the name. It helps distinguish people at a glance and it is a contrast liability — a hashed hue will eventually land on something that fails against white text. The safer answer is one fill.

States

  • Image failed — must fall back to initials, not to a broken image. This is the state that actually occurs.
  • Interactive — where the avatar opens a profile menu, it needs focus and hover. .appbar__avatar is a trigger today and has neither.
  • Deactivated user — a former employee still named in a record. Regulated history does not delete people, so the avatar has to render them without implying they are current.

Responsive behavior

None. Fixed sizes. A group may show fewer before the overflow count at narrow widths.

Usage guidelines

Do

  • Pair it with the name in a list. The avatar is recognition, the name is identification.
  • Hide it from assistive technology when the name is adjacent.
  • Give system actors a distinct treatment.

Don't

  • Use an avatar alone to identify who did something in an audit trail.
  • Let a failed image render as a broken image.
  • Stack more than about five before the overflow count.

Accessibility

  • Decorative by default; labelled only when standalone.
  • Initials are text and inherit the fill's contrast — white on teal-60 measures well, but a hashed per-user hue would not be guaranteed to.
  • An interactive avatar needs a focus ring and an accessible name describing the action ("Your account"), not the person.
